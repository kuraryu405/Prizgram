# Prizgram

> **選考を重ねるたびに、あなたを学習する就活パーソナルエージェント。**

Prizgram は、日本のインターン・新卒就活に取り組む学生向けの AI パーソナルキャリアエージェントです。

求人検索や一度きりのマッチングで終わるのではなく、対話や選考結果から構造化された「就活ペルソナ」を継続的に更新し、その変化した文脈を次の求人探索・推薦・意思決定に反映します。

## なぜ Prizgram なのか

就活ノウハウへのアクセスには格差があります。強い OB/OG ネットワーク、キャリア支援、就活コミュニティを持つ学生は実践的な情報を得やすい一方、そうした環境を持たない学生は同等の支援にアクセスしづらい状況があります。

Prizgram は、断片的な経験や選考結果を継続的に更新される個人モデルへ変換し、そのモデルを求人探索そのものにも利用することで、この格差を縮めることを目指します。

ユーザーが理解できるようにする対象は次のとおりです。

- 自分は何が得意なのか
- どのような企業・職種が合うのか
- 現在どこにギャップがあるのか
- 次にどの求人を見て、何をすべきか

## コアループ

```text
ヒアリング / 対話
        ↓
構造化されたペルソナ
        ↓
検索条件生成 → 求人 API で候補探索
        ↓
求人の構造化・3軸スコアリング
        ↓
応募 / 選考結果
        ↓
フィードバック & 承認済みペルソナ更新
        ↺ 次回の求人探索・再スコアリングへ
```

Prizgram の中心はこのフィードバックループです。新しい選考結果を得るたびに、保存求人の評価だけでなく次に探す求人の条件も更新され、推薦や支援がより有用になることを目指します。

## MVP

初期 MVP では、次の4機能に集中します。

1. **ペルソナ生成**  
   対話形式のヒアリングから、経験・スキル・価値観・志向性・強み・弱みを抽出します。

2. **求人・インターンの自律探索と取り込み**  
   最新の承認済みペルソナから検索条件を生成し、外部利用が許諾された求人検索 API を Tool として候補を取得します。API で取得できない求人は手動入力できます。

3. **説明可能な求人スコアリング**  
   ペルソナと求人・インターンの要件を比較し、単一のブラックボックスなマッチ率ではなく、複数軸のスコアと根拠を提示します。

4. **選考管理とリマインド**  
   応募企業、選考ステータス、面接日程、ES 締切、内定承諾期限などを一元管理し、優先度の高い次のアクションを提示します。

選考結果とユーザーの振り返りからペルソナ更新候補を生成し、ユーザーが承認した内容のみを次の version に反映します。更新後のペルソナは保存求人の再評価と次回求人探索に利用します。

## 求人データの取得方針

MVP では Careerjet 等の、外部利用を前提とした求人検索 API を 1 provider 利用する想定です。provider 固有のレスポンスは共通の `JobSnapshot` に正規化し、手動入力求人と同じ downstream pipeline で扱います。

保存する求人には、可能な範囲で以下の provenance を保持します。

- source / provider
- provider 側の external ID
- source URL
- 取得日時
- content hash

Prizgram 自身が求人媒体を独自に scraping / crawling して巨大な求人 DB を構築することは MVP の対象外です。求人 API は候補発見・取り込みまでに利用し、応募操作は行いません。

provider 依存は adapter 層に閉じ込め、将来 provider を差し替えられるようにしますが、複数求人 API の高度な aggregation は MVP では実装しません。

## 今後の機能

MVP 検証後は、以下を追加予定です。

- 模擬面接の文字起こし・フィードバック
- ES・志望動機の下書き生成
- 新着求人をトリガーとした定期探索
- 複数求人 provider の統合
- 企業公式情報を使った culture/value evidence の補完

## 説明可能性を前提にした設計

Prizgram は、ユーザーを根拠の分からない単一スコアに還元しません。求人とのマッチングでは、例えば次のような軸を個別に提示します。

- スキル要件充足度
- 企業文化・価値観フィット
- 現在の実力と選考難易度のギャップ
- 各スコアを支える根拠

求人票に企業文化・価値観の根拠が十分に存在しない場合は、LLM が推測で補完せず、根拠不足として不確実性を明示します。

## Human-in-the-loop の境界

Prizgram は、求人探索、情報整理、求人スコアリング、リマインド生成、下書き作成などを自律的に行えます。一方、ユーザー本人を代表する対外的な行為や、本人モデルを確定的に変更する操作には人間の関与を残します。

特に以下を守ります。

- Prizgram は**応募を自動送信しません**。
- 求人媒体への独自 scraping / crawling、ログイン突破、CAPTCHA 回避を行いません。
- ペルソナ更新候補は自動生成できますが、確定にはユーザーの明示承認を必要とします。
- 生成された応募書類は下書きであり、最終編集と提出判断はユーザーが行います。
- 面接分析の対象は模擬面接を想定し、企業本番面接の無断録音は対象外です。
- 求人データの自動取得は公式 API や外部利用が許諾された API を利用します。

## アーキテクチャ

MVP の技術構成は次のとおりです。

| レイヤー | 技術 |
| --- | --- |
| Web / API | Next.js App Router / React / TypeScript / Route Handlers |
| Database | SQLite / Drizzle ORM |
| LLM | OpenAI 互換 API / Structured Outputs / Zod |
| 求人取得 | 外部求人検索 API（MVP は 1 provider） |
| 定期処理 | cron または node-cron |
| 実行環境 | AWS EC2 / Node.js 22+ |

モノレポ構成です。

```text
prizgram/
├── apps/
│   └── web/        # Next.js UI / Route Handlers / server-only services
├── packages/
│   ├── db/         # Drizzle schema / SQLite client / migration
│   └── shared/     # Zod schema / domain type / JSON codec
└── docs/
    ├── product.md
    └── architecture.md
```

## プロダクト原則

1. **継続的に学習する** — 選考結果をユーザーのモデル更新と次回求人探索に反映する。
2. **推薦理由を説明する** — スコアだけでなく根拠と不足情報を提示する。
3. **意思決定権をユーザーに残す** — Agent は支援し、最終判断と提出は本人が行う。
4. **情報格差を縮める** — 強い個人ネットワークや求人探索ノウハウがなくても体系的な就活支援へアクセスできるようにする。
5. **効果を測定する** — 作ったこと自体を成果とせず、本当に結果が改善したかを検証する。

## 開発

Node.js 22 以上と pnpm が必要です。

```bash
cp .env.example .env
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

変更前後に次の品質ゲートを実行します。

```bash
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
```

LLM と求人 provider の API key は server-only の環境変数として設定し、リポジトリや client bundle に含めないでください。DB migration と詳細な設計は [`docs/architecture.md`](docs/architecture.md) を参照してください。
